# Design System Checker — UI Audit

**Catch design-system drift in Figma, one selection at a time.**

Design System Checker by **Design OS** reviews selected frames and sections for colors, typography, and spacing that do not follow your design system. It is particularly useful when reviewing AI-assisted UI, but it works with any Figma design.

> **Scope:** Selection only. The plugin never scans an entire page, and it does not attempt to determine whether a design was generated by AI.

## What it checks

| Check | Finds | Suggested action |
| --- | --- | --- |
| **Colors** | Solid fills and strokes without a bound color variable | Bind to the nearest available variable |
| **Typography** | Font families outside your **Brand fonts** list and text without a text style | Review or apply a matching text style where available |
| **Spacing** | Auto-layout gaps, padding, and measurable edge insets outside your **Spacing** scale | Snap to the nearest allowed value |

Color suggestions use available local and team-library variables through Figma's plugin API. Text-style suggestions depend on the styles available in the file.

## How it works

1. **Select a frame or section** in Figma. The audit runs automatically and updates when you change the selection.
2. **Review findings** with the layer name, issue, reason, and suggested fix. Select any finding to locate its layer on the canvas.
3. **Apply a suggested fix** where one is available.
4. Click **Mark on canvas** to add issue annotations only when you want them. Use **Clear** to remove the marks added by the plugin.
5. Click **Copy report** to paste a selection-specific issue summary into a ticket or review.

The compact **Reference settings** panel lets you specify allowed spacing values (for example, `4, 8, 12, 16, 20, 24`) and permitted font families.

## Run locally

This is a plain JavaScript Figma plugin; **no build step** is required.

1. Download or clone the repository.
2. In **Figma Desktop**, create a development plugin to obtain your own Figma-assigned plugin ID.
3. Replace the placeholder `id` in `manifest.json` with that ID. Keep the rest of the manifest unchanged.
4. In a Figma Design file, choose **Plugins → Development → Import plugin from manifest…** and select this repository's `manifest.json`.
5. Launch **Design System Checker — UI Audit** from your development plugins, then select a frame or section.

**Already registered the plugin?** Keep your existing Figma-assigned plugin ID when updating its source files. The repository uses a placeholder ID so it does not impersonate an existing registration.

## Privacy and limitations

- **No external network access:** the manifest declares `networkAccess.allowedDomains` as `["none"]`. The plugin uses Figma's APIs and does not send your designs to an external service.
- **No AI API:** “AI slop” describes design-system inconsistencies, not a determination of a design's origin.
- **Selection only:** only selected frames or sections are audited. Component instances and library components are skipped.
- **Available design-system resources:** variable and style suggestions depend on what Figma makes accessible in the current file and connected team libraries.
- **Canvas marks are opt-in:** annotations are created only after **Mark on canvas** is clicked; a fallback overlay is used where annotations are unavailable.
